# cj-algo-study

CJ 올리브네트웍스 DX 직무 코딩 테스트 준비를 위한 알고리즘 스터디

개인 과제에서는 AI를 학습 도구로 활용할 수 있지만, 작성한 코드와 알고리즘을 스스로 이해하고 설명하는 것을 원칙으로 합니다.

모의 코딩 테스트에서는 AI를 사용하지 않고 개인의 문제 해결 능력을 점검합니다.

## 🎯 스터디 목표

- 문제의 조건과 입력 크기를 바탕으로 알고리즘 유형을 파악한다.
- 알고리즘 선택 이유와 풀이 전략을 설명할 수 있다.
- Java 또는 Python을 주 언어로 선택하여 해결 코드를 작성한다.
- 작성한 코드의 시간복잡도를 분석할 수 있다.
- 다른 팀원의 코드를 읽고 구체적인 리뷰를 제공할 수 있다.
- AI에 의존하지 않고 풀이 전략과 코드 동작을 설명할 수 있다.
- 제한 시간 안에 문제를 분석하고 구현하는 실전 감각을 기른다.

<a id="workflow"></a>

## 🗓️ 진행 방식

### 주간 과제

1. 주차별 Wiki에서 학습 내용과 과제를 확인합니다.
2. 개인 브랜치에서 과제 문제를 해결합니다.
3. 문제 파일에 풀이 전략과 시간복잡도를 작성합니다.
4. 매주 화요일 `23:59`까지 Pull Request를 생성합니다.
5. 팀원 1명 이상의 리뷰와 승인을 받습니다.
6. 리뷰 내용을 반영한 후 `master` 브랜치에 병합합니다.

### 오프라인 스터디

- 매주 수요일 또는 목요일 중 하루에 진행합니다.
- 모의 코딩 테스트 문제는 스터디 당일 공개합니다.
- 모의 코딩 테스트는 약 2시간 동안 진행합니다.
- 모의 테스트에서는 AI를 사용할 수 없습니다.
- 테스트 종료 후 풀이 전략과 코드를 공유합니다.
- 미완성 문제도 접근 방법과 막힌 지점을 공유합니다.
- 종료된 모의 코딩 테스트 문제는 해당 주차 Wiki에 기록합니다.

<br/>

```text
주차별 과제 공개
        ↓
개인 문제 풀이
        ↓
화요일 23:59까지 PR 제출
        ↓
팀원 1명 이상 코드 리뷰
        ↓
수요일 또는 목요일 오프라인 모의 코테
        ↓
풀이 공유 및 피드백
        ↓
리뷰 반영 후 PR 병합
```

<a id="solution-rules"></a>

## 💻 문제 풀이 규칙

각 문제 파일의 상단에 풀이 전략과 시간복잡도를 작성합니다.

### Java

```java
/*
 * 전략: 배열을 정렬한 뒤 투 포인터를 사용하여 목표값을 찾는다.
 * 시간복잡도: O(N log N)
 */
```

### Python

```python
# 전략: 배열을 정렬한 뒤 투 포인터를 사용하여 목표값을 찾는다.
# 시간복잡도: O(N log N)
```

알고리즘 이름만 작성하지 않고, 해당 알고리즘을 문제에 어떻게 적용했는지 간단히 설명합니다.

<a id="branch-convention"></a>

## 🌿 Branch Convention

`master` 브랜치에 직접 push하지 않습니다.

### 형식

```text
week{두 자리 주차}/{영문 이름}
```

### 예시

```text
week01/jinyoung
week02/minsu
```

### 규칙

- 주차는 두 자리 숫자로 작성합니다.
- 이름은 영문 소문자를 사용합니다.
- 매주 새로운 브랜치를 생성합니다.
- PR 병합 후 해당 브랜치를 삭제합니다.

<a id="pr-convention"></a>

## 🔀 Pull Request Convention

### PR 제목

```text
[Week {주차}] 이름 - 주제
```

예시:

```text
[Week 01] 정진영 - 자료구조 기반 구현
```

### PR 마감

```text
매주 화요일 23:59
```

### PR 본문

```markdown
## 리뷰 요청

- 문제 2의 이분탐색 종료 조건을 중점적으로 확인해주세요.

## 참고사항

- 문제 3의 반례를 확인할 때 AI를 사용했습니다.
```

특별한 내용이 없다면 `참고사항`에 `없음`을 작성합니다.

<a id="review-guidelines"></a>

## 👀 Code Review Guidelines

모든 PR은 팀원 1명 이상의 리뷰와 승인을 받아야 합니다.

리뷰어는 다음 중 하나 이상에 관한 구체적인 의견을 작성합니다.

- 알고리즘 선택
- 풀이의 정확성
- 시간복잡도
- 예외 케이스
- 코드 가독성
- 개선 가능한 구현 방식
- 다른 풀이 방법

`확인했습니다`, `LGTM`, `수고하셨습니다`와 같은 메시지만 작성한 리뷰는 유효한 리뷰로 인정하지 않습니다.

- 병합 가능: `Approve`
- 수정 필요: `Request changes`
- 질문 또는 제안: `Comment`

최소 1개의 `Approve`를 받은 후 PR을 병합합니다.

<a id="commit-convention"></a>

## 📝 Commit Convention

```text
<type>: <변경 내용>
```

| 타입       | 설명                  | 예시                            |
| ---------- | --------------------- | ------------------------------- |
| `solve`    | 새로운 문제 풀이      | `solve: 문자열 압축 문제 풀이`  |
| `fix`      | 오답 또는 오류 수정   | `fix: BFS 방문 처리 시점 수정`  |
| `refactor` | 코드 구조 개선        | `refactor: 거리 비교 로직 개선` |
| `docs`     | 문서 수정             | `docs: 3주차 Wiki 링크 추가`    |
| `chore`    | 디렉터리 및 설정 변경 | `chore: Java 풀이 폴더 생성`    |

가능하면 문제 하나당 하나의 커밋으로 분리합니다.

<a id="ai-guidelines"></a>

## 🤖 AI Usage Guidelines

### 개인 과제

개인 과제에서는 AI 사용을 허용합니다.

- 알고리즘 힌트와 접근법 검증
- 시간복잡도 검증
- 반례 탐색
- 오류 원인 분석
- 코드 개선 방법 확인

다만 다음 원칙을 지켜야 합니다.

- AI가 생성한 코드를 이해하지 않고 제출하지 않습니다.
- 제출한 코드의 알고리즘과 동작을 직접 설명할 수 있어야 합니다.
- 알고리즘 선택 이유와 시간복잡도를 AI 없이 설명할 수 있어야 합니다.
- AI를 사용했다면 PR의 `참고사항`에 사용한 문제와 범위를 기록합니다.

### 모의 코딩 테스트

모의 코딩 테스트에서는 다음 행위를 금지합니다.

- 생성형 AI 사용
- 문제 해설 및 타인의 풀이 검색
- 다른 스터디원과의 대화
- 테스트 종료 전 코드 및 풀이 공유

모의 테스트의 목적은 제한 시간 안에 문제 유형을 파악하고 적절한 알고리즘을 스스로 선택하는 것입니다.
